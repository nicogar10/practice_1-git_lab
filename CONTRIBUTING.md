# Contributing

Thank you for your interest in this project.

## Branching Strategy

Create a new branch when you want to make changes to the project.

Use a clear name for the branch, for example:

* `feature/new-feature`
* `fix/bug-fix`
* `docs/documentation`

Do not make changes directly to the `main` branch.

## How to Contribute

1. Clone the repository.
2. Create a new branch for your changes.
3. Make your changes in the project.
4. Check that the changes work correctly.
5. Commit your changes with a clear message.
6. Push your branch to GitHub.
7. Create a Pull Request to the `main` branch.

## Code Changes

When making changes to the project:

* Keep the existing code structure.
* Do not change the code if it is not necessary.
* Add comments or Javadoc when needed.
* Use clear names for classes, methods and variables.

## Pull Requests

When creating a Pull Request:

* Explain what changes you made.
* Check your changes before creating the Pull Request.
* Make sure the project is working correctly.

## Commit Messages

Use clear and simple commit messages that explain the changes.

Example:

`Commit 1: Added Javadoc documentation to Java classes`
